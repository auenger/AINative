// 核心能力 01 · AGENT RUNTIME

主流 Coding Agent，统一接入

一套 AgentRuntime trait 接口，四种通信协议并行运行。Settings 一键切换 Agent 后端，前端代码无需改动。

CLI PIPE

NDJSON 子进程

Claude Code — claude -p --output-format stream-json 直接子进程调用

SDK SIDECAR

Node.js 桥接

Claude Agent SDK — 通过 agent-sdk-bridge.mjs Sidecar，绕过 CLI 限流

PIPE

Stdio 管道

Claude Code / Cursor / OpenCode — NDJSON 管道协议统一接入

ACP

JSON-RPC 2.0 双向 RPC

Codex / Hermes / Kiro / Kimi / Pi — ACP 协议双向通信，支持请求、通知和服务端发起的审批

ARCHITECTURE

统一架构

AgentRuntime trait + RuntimeRegistry + RuntimeDetector + RoutingEngine — 供应商无关的 Agent 编排层

开发不绑定任何单一 Agent 供应商 — 今天用 Claude Code，明天切 Codex，后天上 Hermes，一行前端代码不用改。
// 核心能力 02 · FEATURE WORKFLOW

FDD 驱动的 工程级 harness

内嵌的工作流引擎以 Feature-Driven Development 为设计思想，把"跟 AI 聊天写代码"变成"按工程流程交付特性"。

01
Build Overall Model
→
/init-project + project-context.md
02
Build Features List
→
/new-feature + /split-feature
03
Plan by Feature
→
queue.yaml 依赖排序 + 优先级
04
Design by Feature
→
spec.md 技术方案 + task.md 任务拆解
05
Build by Feature
→
/implement-feature + /verify-feature
SPEC

完整规格文档

每个特性有 spec.md — 需求描述、技术方案、验收标准、Gherkin 场景

TASK

原子任务拆解

每个特性有 task.md — 拆成 2-5 分钟可执行的原子任务

CHECK

验收检查

每个特性有 checklist.md — Gherkin 场景验证，通过才算交付

DAG

依赖关系显式建模

queue.yaml 构建 DAG — 前置特性先完成，上下文自动传播到后续特性。不是随便写代码，是按依赖关系有序交付。

ISOLATION

Git Worktree 物理隔离

每个特性独立 git worktree + 独立文件系统，互不干扰。完成的特性归档到 archive，下次开发可回溯参考。

垂直切片，不是水平分层 — 传统开发按技术层分工（前端组、后端组、DBA 组），FDD 按业务特性垂直切。AI Agent 天然适合这种方式 — 一个 Agent 同时覆盖所有技术层，不存在技术筒仓问题。
